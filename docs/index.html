GistLattice Documentation

Memory infrastructure for Python agents.

GistLattice is a core-only Python library for retrieval, hydration, and consolidation of long-lived memory. It is designed to stay in-process, stay provider-agnostic, and stay small enough to embed in your own agent loop.

Quick Start

The default configuration uses in-memory stores, so you can get started without Redis, Neo4j, or Qdrant. You still need to provide an LLM adapter through Settings.llm_factory or Settings.llm_factory_path. 

import asyncio

from gistlattice import Settings, build_default_service


async def main() -> None:
    service = build_default_service(
        Settings(
            environment="test",
            llm_factory_path="my_project.providers.build_my_provider_llm",
        )
    )

    retrieval = await service.retrieve(
        tenant_id="tenant-a",
        user_id="user-a",
        query="Help me plan my next task.",
    )
    print(retrieval.hydrated_context)

    job = await service.queue_consolidation(
        tenant_id="tenant-a",
        user_id="user-a",
        prompt="Help me plan my next task.",
        response="Here is a memory-bearing response from your own app.",
        request_id="req-123",
    )
    analysis = await service.consolidate(job.job_id)
    print(analysis.gist)


asyncio.run(main())

Public Surface

The package root exports only the small library surface users are expected to rely on.

Symbol Purpose
Settings Runtime configuration model and environment loader.
build_default_container(...) Builds a configured runtime container.
build_default_service(...) Builds the ready-to-use memory service.
GistLatticeContainer Holds backend implementations and runtime state.
GistLatticeService Provides retrieval, hydration, and consolidation APIs.

Architecture

GistLattice is built around a single service layer. It stays in-process and does not expose HTTP routes in this repository. 

Your Python app
  -> GistLatticeService
  -> GistLatticeContainer
  -> LLM client
  -> Episodic store
  -> Semantic store
  -> Queue broker
  -> Consolidation worker
  -> long-term memory stores

The public flow is simple: retrieve memory, hydrate context, queue consolidation, then let the worker finalize it.

Backends

Layer Options
LLM adapter Required, provided through Settings.llm_factory or Settings.llm_factory_path
Episodic store memory, qdrant
Semantic store memory, neo4j
Queue memory, redis
Custom LLM adapters For provider-agnostic usage, point Settings.llm_factory_path at a factory or pass a callable to Settings.llm_factory. The adapter only needs embed_text(...) and analyze_interaction(...).

Provider Adapters

GistLattice includes ready-made provider factories for OpenAI, Gemini, Ollama, and Anthropic. OpenAI, Gemini, and Ollama can provide both embeddings and memory analysis. Anthropic is analysis-only and needs a separate embedding provider.

See the full guide in Provider Adapters for install extras, environment variables, and examples.

Configuration

Configuration comes from environment variables via Settings.from_env(). For Python-native usage, you can also construct Settings directly and pass a callable to Settings.llm_factory.

Variable Purpose
GISTLATTICE_ENV Runtime environment name.
GISTLATTICE_LLM_FACTORY_PATH Import path for a custom LLM factory.
GISTLATTICE_EPISODIC_BACKEND Episodic memory backend.
GISTLATTICE_SEMANTIC_BACKEND Semantic memory backend.
GISTLATTICE_QUEUE_BACKEND Consolidation queue backend.
GISTLATTICE_MEMORY_LIMIT Default number of memories to retrieve.

Functions

The main service methods you will call are retrieve(...), hydrate_context(...), build_hydrated_prompt(...), queue_consolidation(...), and consolidate(...).
